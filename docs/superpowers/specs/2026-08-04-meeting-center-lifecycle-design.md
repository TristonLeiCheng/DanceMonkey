# 会议中心生命周期工作台设计

## 目标

将会议中心工作台改为“会前准备 → 会中记录 → 会后跟进”的文本优先工作区。保留现有会议库、日历、行动项、决策、例会、模板和统计能力，但会议中的主界面只突出当前会议的议程、人工笔记、AI 整理结果与收尾动作。

## 约束

- 应用级最左侧 WPF 导航栏不改动；会议中心 WebView 内不新增左侧应用导航。
- 不提供录音、麦克风、实时转写、波形、说话人或任何暗示语音识别的界面与文案。
- AI 仅基于议程和用户手工输入的会议笔记生成纪要、决策和行动项。
- 继续使用现有 WebView2 ↔ `MeetingHubService` 通讯和本地会议存储。

## 工作台布局

顶部为三阶段生命周期条，当前阶段由会议状态推断；下方显示会议主题、时间、参与人、项目、状态及自动保存提示。工作区采用三列：左列为议程导航和元信息收起入口；中列为结构化人工笔记编辑区，支持选择文字转行动项或决策；右列为 AI 依据当前笔记整理出的决策、行动项和待确认事项。主按钮为“结束会议并整理纪要”。

## 行为与数据流

编辑器继续写回 `WorkbenchDto`，并通过既有 `setWorkbench` 消息同步到服务层。新 `completeMeeting` 消息先标记工作台为已结束并填写结束时间，再调用既有文本纪要生成逻辑；没有 API 密钥或生成失败时保留手工笔记和状态，不丢失内容。保存、复制、同步 ZenTask、会议库和其他非工作台页面保持既有行为。

## 验证

为 `meeting-hub.html` 添加 PowerShell 合约测试，验证生命周期主结构、文本笔记编辑器、文字转行动项/决策动作、无语音关键词与无内嵌左侧应用导航；再执行 .NET 解决方案构建与该合约测试。
