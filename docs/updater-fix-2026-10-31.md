# macOS 自动更新修复

用户反馈：下载 → 解压 → “检查或下载更新失败，请稍后重试”。旧版本没有保存阶段错误，失败后立即删除临时目录，因此无法还原历史失败的原始报错。当前 GitHub 公开 v3.15.0 ZIP 在真实 Electron 中下载、校验通过。

完整应用测试复现了同类故障：使用 macOS `ditto -c -k --keepParent` 生成的 ZIP 经现有 tar 解压后，框架符号链接旁残留 14 个 AppleDouble `._` 元数据文件。`codesign --verify --deep --strict` 报 `unsealed contents present in the root directory of an embedded framework`。旧界面将该错误显示成笼统的下载失败。

修复在检查应用内链接之后，只移除具有 AppleDouble 魔数及版本头的 `._` 普通文件，不跟随符号链接、不删除普通点文件；随后仍执行原来的版本、架构、完整签名、签名团队和宠物资源校验。不重新签名，不跳过校验。

另修复 macOS 路径别名导致的启动确认失败：`process.execPath` 可将 `/var` 解析为 `/private/var`，旧代码按字符串比较后不确认启动，最终回滚。现按真实路径比较，并保留更新目录必须为应用同级目录的限制。

下载改为流式写入临时文件并显示进度，失败 GET 最多重试三次，使用同一网络配置；完整响应才替换下载目标。增加无进度超时、空响应与长度检查，SHA256 校验采用固定内存缓冲。失效的暂存文件允许重新检查下载。

错误按下载、校验、解压、内容、签名和安装准备分别提示，保留 `userData/update-logs/last-error.json` 与 `apply-update.log`；设置页的失败状态可打开日志。日志不保存配置、请求头或下载 URL。

验证：42 项更新专项测试、603/603 项全量 Node 测试、真实 GitHub 在线下载与签名校验，以及 `npm run test:e2e:update:mac`。最后一项使用隔离目录中的完整签名应用、含元数据的 ZIP、真实 Electron 重启，检查启动确认、旧包清理和笔记标记保留；不会读写用户笔记库。

本机 `/Applications/DanceMonkey.app` 已通过同一安装器更新为本地修复版 v3.16.1，并正常退出旧实例、重启、确认启动和清理旧应用备份。已核对安装后的 ASAR 与本地构建一致、七个修改的运行模块与源码一致，严格签名有效，8 份笔记的 SHA256 和关键偏好设置保持不变。界面已显示 v3.16.1，手动检查更新返回“当前已是最新版本”。
