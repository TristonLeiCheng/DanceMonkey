# DM (DanceMonkey)

Windows / macOS 桌面常驻的磨砂玻璃笔记与待办应用。

## 预览

无需安装依赖：

```powershell
npm run dev
```

打开 `http://127.0.0.1:5173`。预览页可切换右缘细条、快捷轨与笔记面板三种形态。

笔记本、笔记、待办、搜索全部收在右侧同一个面板内：顶栏点「笔记本」或「搜索」即在面板内切换，不会另开窗口。快速笔记与任务输入采用不透明卡片背景，支持深浅主题，避免桌面内容干扰文字阅读。

右侧快捷轨自上而下依次为 **AI、任务、程序主入口、全屏截图、搜索**。全屏截图直接进入现有截图操作窗口。

右侧快速笔记顶栏的“展开”按钮会打开完整工作区。完整页面包含：

- **AI 问答**：与快捷面板共用对话记录与 API 配置；提供提示卡片、可自动增高的输入区、模型和提示词选择，以及更易读的 Markdown 回复。完整工作区支持复制原文、失败重试；停止生成会保留已有回复，查看上文时不会被新内容强制滚到底部。
- **人物分身**：导入文章、笔记和聊天记录，预览并编辑人物卡；按人物独立聊天、纠正、更新和恢复历史版本
- **截图与 AI 分析**：`Ctrl+Shift+S` 全屏截图、`Ctrl+Shift+R` 框选截图；结果可复制、保存到笔记，并用视觉模型分析画面
- **软件设置**：通过快捷键、桌面宠物、笔记同步、网络代理（Windows）、关于与更新选项卡分类配置；切换选项卡保留未保存的输入，快捷键、宠物与代理统一保存，GitHub 同步和应用更新使用各自的操作按钮
- **桌面宠物**：恢复旧版 13 种像素角色、情绪和生活动画、点击互动、拖动定位、任务气泡提醒与防休眠；支持 Windows / macOS
- 真实本地 `.md` 文件与递归文件夹树
- 新建、重命名、删除文件夹和笔记；固定根目录入口，新建时可选择目标文件夹
- 多本地笔记库切换，各库独立目录树和展开/折叠状态
- Markdown 编辑、实时预览与分栏模式
- 650ms 自动保存，以及 `Ctrl+S` 手动保存
- `Ctrl+P` 快速文件查找
- 可调整宽度的文件树，以及可拖动的编辑/预览分栏
- 玻璃、纯色、纸张三种界面效果及深浅主题
- **Zen Task**：读写旧版 `Journal/task-module.json`，支持优先级、RACI、能量、截止日期
- **项目管理**：里程碑及任务进度、生命周期与健康度、每周进展记录、风险提醒、任务列表/看板、归档恢复和 Markdown 笔记关联；可从笔记选段批量生成带来源的任务
- **快速访问**：系统路径探测 + 旧版 `config.json` 的 `quickLinks`

桌面知识库与旧版 DanceMonkey 共用 `%AppData%\DanceMonkey\config.json` 中的
`notesRootPath`；未配置时使用“文档”目录下的 `NoteVault`。快速便签对应
`Journal\Stickies` 中的 Markdown 文件，因此升级无需迁移笔记。

### 桌面宠物

在 **软件设置 → 桌面宠物** 勾选开启并保存，或使用托盘菜单里的 **桌面宠物**。可选择小人、猫、狗、兔子、狐狸、大鹅、蟑螂、蚊子、水豚、青蛙、企鹅、乌龟、刺猬，尺寸为 48 / 68 / 96 / 128 px。

新增 **工程师** 皮肤（基础版），使用透明 PNG 图集和平滑缩放，支持挥手、开心跳跃、工作与阅读动作；保留全部 13 种旧像素皮肤。资源规格、动作映射及验收说明见 [工程师 说明](docs/foss-pet.md)。

宠物外形通过实时动画卡片选择，分为动画伙伴与像素伙伴；每张紧凑卡片可独立切换角色动作，支持暂停播放和深浅预览背景，点击卡片后保存设置才应用到桌面。

像素伙伴已重绘为圆润大头比例，增加柔和明暗、眼睛高光与物种细节，支持短眨眼、呼吸及九种生活状态。桌面与设置预览共用绘制；[动态预览与前后对比](docs/pixel-pets-preview.html) / [优化说明](docs/pixel-pets.md)。

新增 **绒绒兔**：奶油白绒毛、弯耳尖与棉花球尾巴，包含眨眼、蹦跳、挥爪、洗脸、打盹等9组动作。[预览与素材说明](docs/fluffy-rabbit.md)。

新增 **抱贝壳的小海獭、小熊猫咖啡师、团子小龙**，各有 9 组透明动画和专属互动台词。在宠物外形中选择并保存即可使用；[动作预览](docs/new-companions-preview.html) / [素材说明](docs/new-companions.md)。

v3.9.0 修复更新或重启后恢复默认宠物：暂不支持的角色选择会保留，菜单只写入单项修改；打包校验角色素材，Mac 更新在安装前检查当前角色兼容性。[修复说明](docs/pet-preferences-persistence.md)。

单击宠物会显示物种专属台词，连续互动后变开心；双击打开主界面，拖动可移动并保存位置。右键菜单可调整大小、防休眠，打开 AI、笔记、待办和截图，或关闭宠物。宠物周围的透明区域允许点击下方桌面；切换或移除显示器后会自动回到可见区域。

**键盘交互默认关闭**，每次启动或重新开启宠物都保持关闭。右键宠物选择 **开启交互模式** 后，使用 `←` / `→` 持续左右行走，`空格` 跳跃；松开方向键停止，跳跃自动落地，按住空格不会连续起跳。宠物会落到当前显示器工作区底部，并限制在该工作区内（避开菜单栏、Dock / 任务栏）。工程师和动画伙伴使用对应动作图集，旧像素伙伴使用原有帧与轻微步行动画。

按 `Esc`、右键选择 **关闭交互模式**、切换到其他应用或隐藏宠物会退出；更换外形／大小、保存设置、显示器变化也会结束本次交互。模式不持久化，不注册全局方向键或监听其他应用输入。交互期间左键拖动和点击互动暂停，退出后恢复；位置仅在退出时保存，运动过程中不逐帧写配置。当前版本在开启交互时所在显示器内行走。

**macOS 桌面图标互动**：仍需右键宠物选择 **开启交互模式**。露出桌面图标后，沿左右方向走近图标所在列；气泡出现“上方「文件名」· 空格跳上”时按空格，宠物会辅助跳向该图标，并在下降时站到图标顶部。较高的图标也会相应提高跳跃高度；空中按方向键可以接管横向移动。站在图标上可以继续左右行走或跳跃，走出边缘后会落下。靠近图标时会显示名称。

**抱起和携带动画**：开启交互模式后，走到图标旁边或跳到图标上，气泡提示 `E 抱起` 时按 `E`。宠物会伸手，将图标影像抱到胸前；携带时可继续左右行走、转向和空格跳跃。再次按 `E` 播放放下动画，影像落到身旁后消失。每次只抱一个，按住 `E` 不会反复切换。过远的上方图标需要先跳近，不能远程拿起。

桌面原图标始终留在原处；携带的是本次拿起时的视觉快照，不改变文件路径、内容和图标布局，也不会在放下处生成文件或碰撞平台。即使源图标后来被遮挡或移走，已拿起的影像仍可正常放下。按 Esc、切换应用、隐藏或关闭宠物、更换角色等退出交互操作会立即清除携带状态，重启后不恢复。

只读取 Finder 的图标名称、桌面位置、普通应用窗口边界，以及按 E 时选中项目的系统图标，不读取文件正文，不打开、移动文件或重排图标。系统图标只在抱起时按需获取，失败时使用通用文件图案；文件路径保留在主进程，不开放任意路径给宠物页面。图标由独立、可取消的 AppKit 查询进程输出为 64 × 64 PNG，避免当前 Electron/macOS 组合的原生图标接口崩溃影响应用。每约 1.5 秒刷新可见图标，被普通窗口遮住、移走或删除的图标会失去支撑；4 秒未获得新位置时也会清空旧平台。退出交互立即取消正在进行的查询并清理图标缓存；默认关闭状态不查询桌面。首次使用可能出现“允许控制 Finder”或桌面访问的 macOS 授权；拒绝或超时仍可普通行走和跳跃，授权后重新开启交互即可。

本阶段支持 macOS 的手动排列／贴齐网格桌面。为避免将折叠叠放中的隐藏文件当作平台，叠放和自动排列暂时停用图标碰撞，并在气泡中提示。图标顶部必须留得下整个宠物，过于靠近菜单栏的图标不能站立。位置使用 Finder 图标尺寸的矩形近似；复杂透明窗口、桌面显示特效、多显示器布局仍需更多实机验证。Windows 继续支持键盘行走和跳跃，本阶段未接入其桌面图标。

宠物会自动吃饭、睡觉、工作、阅读、运动或休息；开启情绪变化后，长时间没有互动会无聊、困倦。任务提醒可在设置中单独开启，间隔为 45–240 分钟，读取当前笔记库的待办，优先提示逾期、今日到期及高优先任务，点击气泡打开待办。关闭宠物后停止其定时器并解除防休眠；全屏或框选截图时会暂时隐藏宠物。

Windows 自动沿用旧版 `config.json` 的宠物偏好与悬浮位置，之后将宠物位置独立保存为 `petWindowX` / `petWindowY`。macOS 使用本机配置。浏览器预览不创建桌面宠物窗口。

验证：`npm test`；实际桌面流程：`npm run test:e2e:pet`（使用临时配置和笔记库）。

键盘交互验证：`npm run test:e2e:pet-control` 使用隔离配置、真实 Electron 窗口、生产运动服务与 sandbox preload，覆盖默认关闭、菜单启用、键盘移动、起跳落地、边缘、E 抱起／携带行走／携带跳跃／放下、源图标布局不变、Esc 清理、失焦及旧像素角色。测试的菜单选择使用独立适配器；生产应用没有通过 IPC 开启交互模式的入口。

**macOS 桌面图标定位原型（开发验证）**：运行 `npm run probe:desktop-icons -- --output /tmp/dm-icons.json`，可附加 `--overlay` 显示 20 秒自动关闭、鼠标穿透的红色坐标标记。此工具独立运行，应用启动和开启交互模式均不会调用它；仅查询 Finder，不打开、移动或修改文件。首次查询可能出现 macOS 自动化授权，45 秒超时后退出。报告含文件名称、URL、原始桌面位置和屏幕信息，应保留在本机。

2026-10-26 本机验证：单屏 2048 × 1280、缩放 1，Finder 返回 3 个桌面项目，3 个 `desktopPosition` 均落在显示器内；已与 Finder 桌面截图核对其中心位置。JXA 的点返回 `{x, y}`。普通 `bounds` 返回的是另一视图的矩形，不能直接用作桌面碰撞框。正式碰撞通过 `electron/desktop-icons.js` 读取位置及窗口遮挡，开发标记原型仍保留为独立诊断工具。多屏、Retina 和复杂透明窗口仍需进一步验证。

### 本地笔记库与目录树

- 进入笔记页面、重新打开窗口或切换笔记库时，默认显示**笔记主页**，不再自动打开目录中的模板文件。编辑时可点击左侧「笔记主页」返回，返回前先保存当前笔记；任务中的来源笔记链接仍直接打开对应文档。
- 主页支持快捷创建**空白笔记、知识笔记、今日日记、会议记录、项目概览、人物档案**，标题可留空使用默认名称。无需先初始化 PKB；已有 PKB 库沿用其目录和自定义模板。同名文件自动编号，不覆盖已有内容。
- 使用**近期更新 / 近期创建**切换列表；输入标题或路径即时筛选，按 Enter 打开首个结果，点击「搜索正文」在本地搜索内容。近期列表最多展示 20 篇。
- 显示当前库的笔记总数、近 7 天新建/更新数量及 Markdown 文件容量；不计入模板、系统说明、隐藏目录和图片附件。创建日期优先读取笔记头部的 `created` / `createdAt` 元数据，旧文件使用本机创建时间（编辑、导入或同步后可能变化）；更新日期来自文件修改时间，包含同步更新。
- 主页是动态应用页面，不会自动生成或改写笔记库中的主页 Markdown 文件。主页实现位于 `src/notes-home.js` 和 `src/notes-home.css`；完整隔离测试可运行 `node test/e2e-notes-home.mjs`。

- 左侧底部以低调的笔记库名称和「···」保留选项入口；点击后展开笔记库切换、打开其他笔记库、模板、PKB 设置和全文搜索，平时默认收起。点击菜单外或按 Esc 可收起。打开其他笔记库仍使用系统对话框，不会搬移或复制原笔记。
- 已打开过的笔记库保留在下拉列表中，选择即可切换。每个库独立保存目录展开/折叠状态；切库前先保存当前笔记，保存失败则不切换。
- 「根目录」行右侧可直接新建笔记或文件夹；也可先选中根目录再用「文件」工具栏新建。创建弹窗中的「创建位置」可改为任意现有文件夹。
- 本地 Markdown、快捷便签、Zen Task 与项目随笔记库切换；应用外观、AI 配置及文件夹同步配置仍为全局设置。
- 为避免不同库互相包含文件，不能将一个已登记库的父目录或子目录再登记为另一个库。文件夹同步、GitHub 同步或截图操作进行时，请先结束相关操作再切换。
- 真实目录选择与多库切换仅在桌面版提供，浏览器预览仍使用示例存储。

面板「任务」标签直接操作同一套 Zen Task 数据；「快速访问」可在面板内打开常用路径，
也可跳转完整工作区。

面板中的 **AI** 标签也复用旧版配置里的 API 端点、Key、模型列表和系统提示词。
支持 OpenAI Chat Completions 兼容接口、多轮上下文、Markdown 回复、流式输出、
停止生成、新对话及连接测试。AI 请求会自动使用 Windows 当前系统代理（PAC 或手动代理服务器）。
浏览器预览只展示界面，实际问答与真实 NoteVault 需使用桌面模式。

## 人物分身

**人物档案** 支持手动录入出生年月（`YYYY-MM`，也可填完整日期）、星座、简历和人物事件。事件按行记录日期与经过，编辑或删除对应行即可更新。点击 **保存人物档案**，或 **保存并生成人物卡**；没有导入文件时也能仅根据这些档案生成。资料变化后旧卡片会提示需要更新。

档案中提供 **MBTI 观察测算**：可直接填写类型，或根据你对对方的观察填写 12 道原创题目，点击 **测算并采用结果** 后保存。每题可选“不了解”，持平或信息不足的维度显示 `X`。这是代填的简易倾向记录，并非官方 MBTI 测评或本人自评；可切回手动类型并补充观察依据。模型将档案标为用户提供的信息，不根据星座或类型编造人格、经历和能力。

支持从公司 Microsoft 365 / Outlook 邮箱自动导入某个人的来信：首次连接后，输入人物邮箱，点击 **导入并生成人物卡**；后续点击 **更新邮件并生成**。自动清理引用与签名、去重，人物卡预览保存后生效。微软应用注册、`Mail.Read` 委托权限和首次连接方法见 [Outlook 配置指南](docs/outlook-setup.md)。

在桌面完整工作区左侧选择 **人物分身**：

1. 点击 **新建**，填写人物名称，可选填简介。
2. 在 **资料** 中粘贴文章/笔记，点击 **加入资料**；也可 **导入文件** 或 **从现有笔记选择**。
   文件支持 UTF-8 `.txt`、`.md`、`.markdown`、`.json`、`.jsonl`。每次选取最多 20 个文件，单个不超过 1 MiB；
   每份正文最多 80,000 字符，每个人物最多 40 份、总计 120,000 字符。只读取用户选中的资料，不自动扫描笔记库。
3. 聊天资料选择 **聊天记录**，填写记录中准确的 **目标说话人**。纯文本使用 `姓名：内容`，例如：

   ```text
   小周：要不要先做一个很大的方案？
   林老师：先做一个能验证假设的小实验。
   ```

   JSON 支持消息数组或 `{ "messages": [...] }`；每条消息包含 `speaker` / `name` / `role` 与 `content`，可带 `timestamp`。
   JSONL 每行一条消息。选择聊天类型后也可以直接粘贴这些格式。其他人的话仅作为上下文，不能作为目标人物的观点证据。
   不直接读取微信数据库或私有平台账号；请先导出为支持的格式。
4. 点击 **生成人物卡预览**。模型会分批分析资料，形成概览、知识、思考方式、表达风格和回答边界。
   可以直接编辑预览，点击 **保存此版本** 后才生效。生成失败或停止不覆盖原人物卡。
5. 切到 **对话**，向人物分身提问。每个人物、每个会话独立保存；可新建、切换和删除会话。
   支持流式回答、停止和 `Ctrl / ⌘ + Enter` 发送。失败或取消的轮次不写入历史，输入会保留以便重试。
6. 在 **人物卡 → 纠正 / 更新** 补充一句话，生成更新预览并保存；新资料也可重新生成人物卡。
   **版本** 中可恢复历史内容，恢复会创建新版本。保存时校验资料及卡片版本，避免旧预览覆盖新内容。

**名人示范**提供孔子、老子、李白、爱因斯坦、乔布斯和马斯克六种编辑设计的对话视角。
点击“查看示范”预览思考方式和开场问题，再“添加并开始对话”；取消预览不会写入资料。
添加在本机一次性保存示范说明、人物卡 v1 和空会话，不调用模型。问题按钮仅填入输入框，点击发送才使用 AI。
同一示范重复添加或重启后打开会复用原分身，保留用户改名、编辑和对话；按稳定示范标识去重，不按姓名覆盖用户人物。
删除示范分身后不会自动重建，可从图库再次手动添加。示范卡支持既有的编辑、版本与会话流程。
所有示范明确标为 AI 模拟，不是本人、官方账号或背书；表达风格和生成内容不代表本人真实思想或引语。
示范不包含肖像、声音克隆、私人资料或实时动态；老子的生平与成书年代保留争议说明。

人物分身复用 **AI 设置** 中的 Chat Completions 兼容接口、API Key 和模型。
生成时选中的资料、聊天时检索到的资料与会话内容会提交给该 AI 服务；本地保存不代表云端模型离线处理。
浏览器预览不提供真实导入或 AI 生成，需使用桌面版。无需安装 Python、Agent 宿主或训练模型。

人物档案、原始资料和对话保存在 Electron `userData/personas`，与笔记库和普通 AI 聊天分开；
切换笔记库不切换人物集合。应用的 GitHub/笔记文件夹同步不会自动收录这些资料。
从笔记导入的是快照，之后编辑原笔记不会自动更新人物资料。移除一份资料不会抹除已经保存的卡片、历史版本或旧回答；
可重新生成当前人物卡，或删除整个人物及其本地资料。

每个人物保留最近 20 个卡片版本、最多 20 个会话；每个会话最多 100 条消息、人物总计最多 400 条消息。
到达上限时会明确提示，新建会话或删除不需要的会话后继续。
人物卡是现成模型使用的资料与行为配置，不是训练后的模型权重；模拟回答不代表本人真实表态。

实现基于 MIT 许可的 **Distilly（原同事.skill）**：提示流程固定在提交
`0afc45c29c360ba7bc8260f1bb0bf34e9155f4fa`，上游原文、许可证及改编说明位于 [`vendor/distilly`](vendor/distilly/README.md)。
桌面流程用 JavaScript 实现，资料分块与中文词项检索不需要额外向量服务。

验证：`npm run test:e2e:personas` 使用隔离 Electron 数据目录和本地模拟模型，覆盖导入、预览/保存、流式聊天、纠正、恢复、隔离和重启；不会使用真实 API Key 或发送真实资料。

## 桌面模式

在 macOS 上，从终端运行：

```bash
cd electron-app
npm install
npm run desktop
```

打包当前 Mac 架构的 `.app`、`.dmg` 和 `.zip`：

```bash
npm run package:mac
```

也可以分别运行 `npm run package:mac:arm64` 或 `npm run package:mac:x64`。
产物位于 `out/`。v3.7.0 沿用既有分发方式：Mac 使用 ad-hoc 签名，未做 Apple Developer ID 公证；Windows ZIP 未做代码签名。下载或首次启动可能遇到系统安全提示，本项目不绕过系统安全检查。
如需正式签名，应先配置有效的 Apple Developer ID 和公证凭据，再以 `DM_MAC_SIGN=1` 启用已有打包配置。
macOS 的屏幕截图需要在系统设置中授权「屏幕与系统音频录制」。当前 macOS 版本的
AI 请求会跟随系统代理，但不写入系统代理。首次从 DMG 安装到可写的应用程序文件夹后，即可使用应用内自动更新。

Windows 可用 `npm run package:win` 生成 Forge ZIP。`npm run publish:win` 依次执行 Forge 打包和
升级包准备，包含全部生产依赖，并生成兼容旧版升级器的 `win-x64` ZIP 与升级清单；此命令不上传 GitHub。
在 macOS 交叉打包 Windows ZIP 后运行 `npm run prepare:win-release`，可在
`out/make/release/` 生成兼容 GitHub Latest 更新和旧版清单更新的 `win-x64` ZIP 与 `update-manifest.json`。

Windows 和 macOS 桌面版启动 30 秒后自动检查更新，运行期间每 6 小时检查一次。发现新版后会在后台下载并准备更新，右上角显示 **更新并重启**。点击后会先保存当前笔记，再安装并重启；也可在 **设置 → 关于与更新** 点击 **检查更新**，准备完成后点击 **安装更新**。更新界面不显示更新源或安装路径。

Mac 会按运行架构选择发行版中的 `DanceMonkey-darwin-arm64-*.zip` 或 `DanceMonkey-darwin-x64-*.zip`，不使用 Windows 升级清单。发布新版时需同时上传相应架构 ZIP（现有 `package:mac` 命令会生成 ZIP 和 DMG），版本号必须与应用包一致。更新器会验证包校验和（发行版提供时）、应用标识、版本、架构及完整代码签名；已使用 Developer ID 签名的应用要求新版来自相同签名团队。替换前准备同盘副本，等待旧进程退出后安装；新版完成初始化后清理备份，启动失败或超时会恢复旧版。笔记与用户配置目录不参与替换。只读 DMG、App Translocation 或不可写安装位置需要先将应用移到可写位置。

尚未包含更新器的旧 Mac 版本需手动安装一次包含此功能的新版，之后可应用内更新。

以下 Windows 启动器说明仍适用于 Windows：

双击项目根目录的 `启动DM.bat`（内部调用 `start-dm.ps1`）。缺少依赖时会自动执行 `npm install`。

若本机没有 Node.js，启动器会使用项目 `vendor/node-v*-win-x64.zip` 便携包，自动解压到 `%LOCALAPPDATA%\DanceMonkey\runtime\node`（无需管理员权限）。

程序以独立进程运行，启动脚本确认窗口出现后即可关闭，不会影响程序。要完全退出，单击完整窗口右上角的 **退出**，或悬浮面板右上角的电源按钮；也可使用 **Cmd+Q**（Mac）或 **Ctrl+Q**（Windows）。退出会停止后台任务并等待笔记保存，随后关闭全部窗口；通过启动器运行时也会结束它启动的预览服务。完整窗口的 × 仅关闭窗口，程序继续驻留。

Mac 顶部菜单栏与 Windows 右下角通知区域（系统托盘）显示 DM 常驻图标，菜单提供 **显示主界面** 和 **退出软件**；Windows 单击托盘图标可直接打开主界面。Mac 菜单栏采用随系统深浅色切换的单色图标，并提供 Retina 分辨率。Windows 可通过系统的隐藏图标区域管理图标是否始终展示。Mac Dock 与 Windows 任务栏也保留 DM 图标。点击 Mac Dock 图标可显示主界面；Windows 从任务栏聚焦悬浮面板时会展开面板。Mac 应用菜单及 Dock 的系统退出入口也会执行同样的保存与退出流程。

也可以手动启动：

```powershell
npm install
npm run desktop
```

桌面模式提供透明无边框窗口、始终置顶、失焦收起、本地 JSON 持久化，以及 `Alt+Q` 全局快捷键。程序为单实例运行，重复启动只会唤出已有窗口。

若所在环境（远程桌面、虚拟机等）无法启动 GPU 进程，启动器会自动改用软件渲染重试；也可直接指定：

```powershell
$env:LUMEN_SOFTWARE_RENDER="1"; npm run desktop
```

## PKB 个人知识库（基础版）

完整工作区的「笔记」页提供 **PKB 设置 / 模板 / 全文搜索**（桌面版）。

1. 打开希望使用的本地笔记库，点击 **PKB 设置** 查看新增目录、文件和兼容提醒。
2. 确认后，应用协调两个编辑器保存，再创建缺少的标准目录、模板、总索引与规范。不会自动移动、覆盖或分类现有笔记；已有任务和项目 JSON 继续使用原位置。
3. 点击 **模板** 新建知识笔记、日记、会议记录、人物档案或项目概览文档。新文档包含稳定 ID、类型、日期和敏感等级；项目概览模板不是任务模块中的项目记录。
4. 点击 **全文搜索**，输入关键词后按 Enter。本地搜索文件名和正文，不调用 AI；最多返回 100 条，跳过保险库、隐藏目录、模板和超大文件。它不是向量检索，也不保证索引所有附件。

目录采用 `00_Inbox`、`01_Journal`、`10_Self`、`20_Work`、`30_Knowledge`、`40_Life`、`50_Social`、`60_Health`、`70_Finance`、`80_Vault`、`90_AI`、`99_Archive` 和 `_System`。`_System/pkb.json` 保存库 ID、协议版本与入口路径；不要手工删除或绕过该标记。

**兼容与安全边界：**

- 初始化前建议自行完成全库备份。初始化是可重复的新增操作，不是有回滚保证的全量迁移器。
- 旧便签位置按初始化预览保留；启用后的入口路径由 PKB 配置决定。既有正文和链接不自动改写，旧笔记也不批量添加元数据。
- **`80_Vault` 是分类目录，不是加密保险库。** 身份、医疗、财务等敏感原件建议放到独立加密存储，普通库仅保存适当索引。
- PKB 保护目录包括 `60_Health`、`70_Finance`、`80_Vault`、`90_AI/92_Context`、`90_AI/94_Datasets`、`90_AI/95_Logs`、`00_Inbox/ai-pending`。发现其中有文件时，同步保护会拒绝整次 GitHub / 文件夹同步，不会静默排除后把远端文件当成应删除的内容。初始化不会在这些目录内写说明文件。
- 保护策略不等于加密，不会清除旧远端历史、旧备份，也不约束其他应用或外部同步工具。GitHub 原有附件种类和容量限制仍然适用。GitHub 不上传 `_System/pkb.json`，每台设备都需在本地显式初始化 PKB；未初始化的旧库不会仅因目录名而自动获得保护。
- `sensitivity` 目前是描述字段，不是权限控制。人物档案等放在保护目录之外的资料仍可能同步，请勿仅依赖标签存放隐私数据。
- 本版没有接入 AI 自动分类、上下文读取、审核归档或分库聊天历史；不要把目录存在理解为 AI 隐私隔离已经完成。
- 当前不提供全文链接修复、通用附件管理、自动归档搬迁或全库备份恢复。请先在副本上验证，再整理真实数据。

## GitHub 笔记手动同步

桌面版「设置 → GitHub 笔记同步」可以将当前本地笔记库与一个 **私有 GitHub 仓库**绑定，同步笔记、任务和项目。
离线继续本地编辑；只有点击「预览差异」并确认同步后，才会提交和推送。无需另外安装 Git，
运行时使用 `isomorphic-git`。浏览器预览不能连接账号或同步真实文件。

### 点击完成连接与建库

1. 点击 **连接 GitHub · 网页授权**，在浏览器登录 GitHub。点击 **复制验证码**，在授权页粘贴；完成后应用自动更新连接状态。
   如果浏览器未打开，可点击 **打开授权网页**。
2. 点击 **创建笔记库 · 打开 GitHub**，网页填写仓库名称（例如 `my-notes`），选择 **Private**，由用户确认创建。
   已有仓库可直接选择 **选择已有笔记库**。
3. 点击 **授权笔记库 · 打开网页**，安装或调整 GitHub App 的仓库访问权限；选择 **Only select repositories**，仅授权笔记仓库。
4. 回到应用点击 **已完成，刷新列表**，从下拉列表选择笔记库，再点 **确认选择并进入同步**。
   列表只显示当前 App 已授权且用户有写权限的私有仓库，自动使用默认分支，无需输入 owner、仓库地址或分支。
5. 绑定只保存关联；先预览上传、下载、删除和冲突，再确认手动同步。另一台电脑登录后选择相同仓库即可。

应用只打开固定的 GitHub 官方页面，不会代替用户提交建库表单，也不申请额外 Administration 权限。
网页创建与仓库安装授权是独立步骤；返回应用需刷新列表，不会把“已打开网页”当成“已创建成功”。

### 开发者一次性配置

正式发行时，开发者注册 GitHub App，启用 **Device Flow**，Repository permissions 设置为
**Contents: Read and write**（Metadata 必需只读）；不需要 Webhook、客户端密钥或私钥。
将公开 `clientId` 和 `appSlug` 预置到 `electron/github-app.json`，也可在开发启动时使用
`DM_GITHUB_CLIENT_ID` / `DM_GITHUB_APP_SLUG` 环境变量。预置后普通用户无需配置 App。

v3.4.0 已预置 `dmdesktop` 的公开 App 标识，用户无需填写 Client ID。GitHub App 的可安装范围由拥有者在 GitHub 管理：
面向其他用户发布时，应确认 App 允许其他账号安装。高级设置可填写自有 App 标识或手动指定仓库与分支；这些标识不是访问令牌。

绑定针对当前本地笔记库：切换库后，仓库绑定、同步基准、备份与冲突记录分别保留；新库需要单独绑定，切回原库恢复原绑定。GitHub 登录授权由各库共用。
不提供 API 自动创建仓库、更换某个库已绑定的仓库/分支或自动同步。新设备默认使用文档目录的 `NoteVault`；目录内已有内容会参与预览，不会被当作可丢弃缓存。

### 范围、安全与冲突

- 同步 `.md`、`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`，以及任务数据 `Journal/task-module.json` 和项目数据 `Journal/zentask-projects.json`；每个文件最多 10 MiB，最多 5000 个文件 / 200 MiB。
  JSON 仅允许上述两个精确路径；其他 JSON、应用设置、API Key 或隐藏目录不上传。遇到符号链接、大小写歧义或不兼容路径会停止同步。
- Git 元数据、同步基准、备份及冲突材料存放在 Electron `userData/github-notes`，不放入笔记库。
  GitHub token/refresh token 由系统安全存储加密后单独保存；安全存储不可用时拒绝登录，不明文降级。
- 同步会短暂暂停编辑，完成后刷新完整编辑器、快捷便签及任务/项目数据，避免旧缓存覆盖下载内容。
- 双方修改同一文件、删除与修改相遇时，在同步预览中直接点击解决：**查看双方内容 → 选择处理方式 → 预览解决结果 → 确认并手动同步**，无需打开文件夹复制、改名或编辑文件。
  可逐文件或批量选择**保留本地 / 采用远端**；笔记和图片支持**两份都保留**（本地使用原名，远端自动另存 `.remote-编号` 副本，两份同步到两端）。删除冲突会明确提示哪一端已删除；两份都保留时恢复仍存在的版本。
  双方都存在的 Markdown 支持**拼接成一篇**：保留本地全文，在分隔线和标题后追加远端全文，不自动去重或进行语义合并。文字以纯文本对照，图片可直接预览；长文字对照只显示前 16 KB，处理仍使用完整内容。
  选择及预览解决结果不会修改文件；确认同步时重新检查本地内容与远端版本，变化后要求重新预览。双方原始副本保留在 `conflicts/<编号>/local`、`remote` 及删除说明中，不强制推送、不按修改时间决定覆盖。
- 任务和项目也按整个 JSON 文件判断冲突，不逐条自动合并。两台设备即使修改了不同任务，只要同时改动同一数据文件，也会停止同步并保留双方副本；更换设备前先同步，另一台编辑前先拉取最新内容。
- 同步前会检查任务/项目 JSON 格式，以及两端合并是否会新增任务指向已删除项目或里程碑的关联；发现问题会停止同步。未提交的任务/项目编辑窗口需先保存或关闭，快捷面板中的任务输入草稿会保留。
- 每次实际同步会在 `backups` 下保留同步范围内的本地快照；未完成操作保留恢复记录，下次预览重新协调。
  备份不会自动清理，长期使用需自行检查磁盘空间。
- 不直接同步整个应用数据目录，不与现有「文件夹同步」并发执行；请勿同时用其他程序修改笔记库。
- 私有仓库不是端到端加密；删除文件不会清除 Git 历史。截图可能包含隐私，上传前检查预览。
- 断开连接只删除本机授权凭据，不删除本地笔记或 GitHub 仓库。需要撤销远端授权时，在 GitHub
  Settings → Applications 中撤销 App 授权/安装。

开发验证：`npm test` 使用临时笔记库、模拟授权和隔离 Git 仓库，不上传真实笔记。
Git 传输集成测试需要开发机安装 `git`（应用运行及打包后的用户端不需要系统 Git）；`npm run test:e2e`
会启动隔离用户目录的 Electron，验证根目录新建、笔记库往返切换、分库目录状态、便签/任务隔离及编辑器保存/恢复，不访问真实 GitHub。
真实 GitHub App 授权、企业代理和两台真实设备的互通仍需使用专用测试仓库验收。

## 项目工作台

在「项目」中新建项目，点击项目名称进入详情。项目内添加的任务自动归属当前项目；
列表和看板使用同一份任务数据，可直接用任务上的状态菜单切换待办、进行中、受阻、完成。

通过「关联笔记」选择知识库中的 Markdown 文件，点击即可进入原笔记编辑器。
应用内重命名笔记或文件夹会同步关联路径；外部移动或删除的文件会提示重新关联。
解除关联不会删除原文件。

归档项目会从活跃项目列表移出，保留任务与笔记关联；在「已归档」中可恢复。
旧版 JSON 继续兼容，编辑保留未提交的字段。只有项目名称且无 ID 的旧任务，
仅在名称唯一时解析归属；同名歧义任务需手动指定项目。

数据与界面回归检查：`npm test`。浏览器预览和桌面版共用任务/项目字段更新逻辑，
浏览器示例保存在浏览器本地，不会写入真实知识库。

## v3.8.0 原创话务员兔子

桌面宠物设置新增「话务员兔子」，奶油色长耳、青绿耳麦和日常办公服，包含待机、左右行走、招手、开心、失落、待命、耳麦通话和笔记九组动作。点击互动、开心以及工作/阅读等原有模拟状态会播放相应动画；行走素材保留在预览中，未新增自动桌面游走。耳麦动作仅为模拟动画，不具备真实电话接入能力。默认宠物和用户已有选择不会自动改变。详见 [素材与验收说明](docs/operator-rabbit.md)。
