# Outlook 邮件人物分身：首次配置

适用于公司 Microsoft 365 / Exchange Online 邮箱（微软全球云）。在你登录的邮箱中按人物邮箱筛选来信，并将正文作为人物资料；对方不需要提供密码。首次连接后，日常操作只需输入人物邮箱，点击“导入并生成人物卡”。

## 1. 注册微软应用（一次性）

1. 用公司账号打开 [Microsoft Entra 管理中心](https://entra.microsoft.com/)。确认当前目录是公司的目录。
2. 进入 **身份 → 应用程序 → 应用注册 → 新注册**。
3. 名称填写 `DanceMonkey 人物邮件导入`。
4. 支持的账户类型选择 **仅此组织目录中的账户（单租户）**，然后注册。
5. 在 **概述** 中复制两项：
   - **应用程序（客户端）ID** / Application (client) ID。
   - **目录（租户）ID** / Directory (tenant) ID。

两个 ID 都是类似 `12345678-1234-1234-1234-123456789abc` 的 GUID。不要复制“对象 ID”。它们是应用配置，不是密码。

如果没有“新注册”权限，请将本页交给公司 IT，由 IT 注册应用并提供这两个 ID。

## 2. 配置桌面应用回调

进入该应用的 **身份验证 → 添加平台 → 移动和桌面应用程序**，添加重定向 URI：

```text
http://localhost
```

保存配置。登录时官方 MSAL SDK 会使用临时本机端口；注册时不需要填写端口，也不要填应用预览使用的 5173 端口。

这是桌面公共客户端的授权码 + PKCE 登录。**无需创建客户端密钥、证书，也无需将邮箱密码填入 DanceMonkey。** 不需要为此开启设备代码或用户名密码登录流程。

## 3. 添加邮件权限

进入 **API 权限 → 添加权限 → Microsoft Graph → 委托的权限**，搜索并选择：

```text
Mail.Read
```

点击添加权限。请选择 **委托的权限 / Delegated permissions**。功能只读取邮件，所需邮件权限为 `Mail.Read`；无需 `Mail.ReadWrite`、`Mail.Send` 或应用程序权限。`Mail.ReadBasic` 不包含邮件正文，不能满足人物生成。

`Mail.Read` 的授权范围是登录用户的邮箱，人物邮箱筛选由 DanceMonkey 的查询逻辑执行；微软授权页面不会将权限缩小为某一个发件人。MSAL 还会请求正常登录所需的 OpenID/离线登录范围，以便记住登录并刷新令牌。

若公司禁用用户自行同意应用，请让 IT 在此应用中授予管理员同意，或通过公司的管理员审批流程批准。管理员还可能需要将你的账号分配到该企业应用。无需放开全公司的安全策略。

## 4. 在 DanceMonkey 中连接和导入

1. 启动桌面程序，打开 **完整笔记 → 人物分身**，新建或选择一个人物。
2. 在 **资料 → Outlook 邮件 → 连接设置** 中粘贴租户 ID 和客户端 ID。
3. 点击 **保存配置并连接 Outlook**，在系统浏览器的微软页面登录自己的公司账号，按公司要求完成 MFA 和授权。
4. 返回 DanceMonkey，确认显示正确的“已连接”账户。
5. 输入目标人物的邮箱，选择时间范围（默认近一年），点击 **导入并生成人物卡**。
6. 系统搜索来信、提取正文、清理引用/签名、去重，并生成可编辑预览。点击 **保存此版本** 后即可在 **对话** 中聊天。
7. 后续点击 **更新邮件并生成**。有新增或修改的内容时重新生成预览；资料和已保存卡片都没有变化时跳过模型调用。

点击“停止”可以取消登录或导入。若邮件已保存而模型调用失败，界面会说明资料已保留；修复 AI 配置后可重新生成，无需重复导入。

## 第一版范围与数据行为

- 每个人物绑定一个目标邮箱和一个读取邮件的公司账户，防止更新时混入其他人的资料。换人物请新建分身；换登录账户后，原人物只能由原账户更新。
- 每次按时间倒序检查匹配发件人的最近 **200 封**邮件；页面显示本次检查、添加、更新、重复、跳过数量，以及是否仍有更多邮件。缩小或扩大时间范围不会删除已经导入的资料。超过 200 封时不是全量归档功能。
- 每个人物可保存 **200 封邮件、合计 240,000 个字符**；单封清洗后最多 16,000 字符。超限会明确计入跳过，不截断正文后冒充完整导入。普通文章/笔记/聊天的 40 份、120,000 字符额度独立保留。
- 每次更新重新核对所选范围内最近的邮件，通过邮件标识和正文内容去重；本地已有同封邮件的正文变化会更新原资料。没有后台常驻同步，也不订阅实时通知。
- 手动移除的邮件会留下本地排除记录，防止下次更新又自动加入。远端邮件删除不会自动清除本地已导入的快照；人物卡历史也不会自动重写。
- 默认排除垃圾邮件、已删除邮件及其子文件夹、草稿、自动回复、部分自动通知和代发邮件。只使用目标发件人正文，优先使用 Graph `uniqueBody`；复杂的行内引用仍可能需要人工检查和移除。
- 首期不读取附件，不支持共享邮箱、个人 Outlook.com、PST、公司自建 Exchange 或世纪互联中国云；也不能读取登录用户无权访问的对方邮箱。
- 邮件来源保留主题、发件人、发送时间、邮件标识及可用的原文链接。聊天仍使用现有的人物资料检索与来源引用。

## 数据保存与模型

微软令牌只在主进程使用，缓存用系统安全存储加密后保存于应用数据目录 `outlook/`，不会返回给页面、写入笔记库或加入笔记 GitHub 同步。退出账户会清除本机登录缓存；这不等于撤销公司目录中的应用授权。

邮件正文、人物卡与对话保存在本机应用数据目录 `personas/`。正文当前为受文件权限保护的本地 JSON，不是单独加密的邮件数据库。生成/聊天会把相关资料发送到 **AI 设置** 中配置的服务，请配置公司允许处理这些邮件的模型服务。一次导入从点击按钮时固定 AI 服务配置，过程中改动全局设置不会将后续批次改送另一服务。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 没有应用注册权限 | 让公司 IT 完成第 1–3 步并提供两个 ID |
| 提示需要管理员批准 | 请 IT 批准该应用的 `Mail.Read` 委托权限，必要时分配用户 |
| 回调 URI 不匹配 / AADSTS50011 | 在“移动和桌面应用程序”平台添加准确的 `http://localhost` |
| 登录账户与租户不匹配 | 使用配置目录中的公司账号，核对租户 ID；第一版不支持个人微软账户 |
| HTTP 403 无权读取邮件 | 核对 `Mail.Read` 是委托权限、授权已生效、账号拥有 Exchange Online 邮箱；权限变更后重新连接 |
| 系统安全存储不可用 | 检查 macOS 钥匙串或操作系统凭据存储，程序不会退回明文令牌保存 |
| 找不到正文 | 检查目标邮箱实际发件地址、时间范围，以及邮件是否属于代发、自动回复或仅有引用 |
| 邮件已导入，但没有生成卡片 | 检查 AI 设置、模型服务可用性，然后点击“生成人物卡预览”重试 |
| 已达到邮件容量 | 在资料列表移除不需要的邮件后再更新；移除操作不会改写旧卡片，请重新生成并保存 |
